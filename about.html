A free reference for web animation

How this was made

This site is a working example of scroll-driven animation on the open web. It exists to be looked at, picked apart, and copied. You don't need a framework to make a page move — just a few well-chosen tools and clear intent.

01 Why this exists

Most animated marketing sites are locked behind a build pipeline, a design system, and a half-million dollar agency. You see them, you think I wish I could make that, and the trail goes cold.

This page does not go cold. The whole site is one HTML file (index.html), one Node server (server.js), a handful of hand-illustrated PNG/SVG assets, and two animation libraries. That's it. Right-click and View Source — everything you see is in there.

The goal is to give designers, developers, and curious onlookers a reference they can read straight through. The comments in the code are written for humans, not for me-six-months-from-now.

02 What's actually animated

Four moments do most of the heavy lifting. Each one is a different pattern you can lift and reuse.

Moment 01 / Hero impact

The "NOT" drops, Brady reacts

The page opens calmly: Tom Brady is the GOAT. Then on first scroll, the word NOT drops in red, the word "the" gets struck through, and the photo of Brady cross-fades to a shocked version. Every value (position, opacity, the strike-through line) is tied directly to the scrollbar — so the user is the one driving the punchline.

GSAP ScrollTrigger · scrub timeline
Moment 02 / The accolades pin

Awards stamp down on the page

Brady's championship rings, MVPs, and Super Bowl wins fall onto the screen one at a time as the user keeps scrolling. The trick: the section is pinned in place, and scrolling drives a timeline rather than the page itself moving. It feels like a slide deck advancing, but the user controls the pace.

GSAP ScrollTrigger · pinned scrub
Moment 03 / The puppet

Cartoon Brady dances on cue

The dancing Brady puppet is not video and not CSS — it's a Rive file. A designer drew Brady in twelve named parts (head, torso, arms, hands, legs), then we rigged him in Rive like a marionette. On the page, his dance plays in time with the scroll. Move fast and a hidden "celebration" branch fires.

Rive runtime · state machine + scroll input
Moment 04 / The vote

You vote, the bars race

When you cast a vote, the page rebuilds into a leaderboard. Bars animate from zero to their share of the votes. The numbers are real — they come from a Postgres database that every visitor writes to. Brady is pinned at the bottom regardless of his score.

GSAP tweens · Node + Postgres backend

03 The whole stack

Five tools. No build step. No framework. The browser opens index.html directly.

GSAP Animation engine

Tweens, timelines, and a scroll plugin that lets the scrollbar drive the animation instead of just trigger it. The single most leverage-per-line tool on the page.

gsap.com →

Rive Puppet runtime

A vector-animation format and a tiny browser runtime. Designers rig characters in the Rive editor; the page plays them. Smaller than a GIF, sharper than a video.

rive.app →

Express Server

Six lines of Node code that serve the static files and handle two tiny API endpoints: POST /api/vote and GET /api/votes.

expressjs.com →

Postgres Vote database

One table, five rows, an integer column per candidate. A relational database is wild overkill for this — and exactly the right call once two people are voting at once.

postgresql.org →

Railway Hosting

One platform that runs the server and the database, with a custom domain on top. Push to GitHub, Railway redeploys.

railway.app →

Hand illustration Art

Every face, the crown, the shocked Brady, the puppet rig — all original drawings. The tech is generic. The art is the only thing that makes the page feel like itself.

04 The one pattern to steal

If you only take one thing away from this site, take this: a scrub timeline.

For non-devs

A scrub timeline ties an animation to the scrollbar. Imagine the timeline is a row of frames in a flipbook. The user's scroll position picks the frame. Scroll forward, the animation plays forward. Scroll back, it plays in reverse. The user is in control of the pace, every time.

This is what makes the page feel responsive instead of scripted. There is no autoplay video. There is no "wait for the animation to finish." If you scroll fast, it plays fast. If you scroll slow, it plays slow.

For devs 
// Tie a GSAP timeline to the scrollbar.
// `scrub: true` means scroll progress (0 → 1)
// becomes timeline progress (0 → 1).
const tl = gsap.timeline({
  scrollTrigger: {
    trigger: '.hero',
    start:   'top top',
    end:     '+=1800',   // 1800px of scroll
    scrub:   true,             // ← the magic
    pin:     true,
  },
});

tl.to('.line-not', { y: 0, opacity: 1 })
  .to('#hero-brady', { opacity: 0 }, '<')
  .to('#hero-brady-shocked', { opacity: 1 }, '<');

The whole hero sequence on the home page is built out of three or four tweens like this, stacked on one timeline, scrubbed by scroll. Once you have the pattern, you have most of what every animated landing page on the web is doing.

05 Three real production bugs

The annotated war stories. Each one is in the code with its own comment block.

1. The first scroll always felt sluggish on phones.

The first time a user scrolled, the hero animation lurched. The second time, butter. The cause: GSAP and the browser both do one-time setup work the first time an element animates — calculating tween values, promoting elements to the GPU. We force that work to happen once, up front, by playing the timeline forward and back invisibly: 

index.html — _createHeroST()// Pre-warm the scrub timeline so the FIRST scroll doesn't pay
// GSAP's one-time tween-compilation cost. Jump to end and back,
// the browser does its setup, the next real scroll is smooth.
_notDropTl.progress(1, false);
_notDropTl.progress(0, false);

2. Desktop saw 2 votes. Mobile saw 10.

Same database, same endpoint. The host's edge CDN was caching the JSON response, and different visitors were getting different cached copies. One header solved it: 

server.js — /api/* middlewareapp.use('/api', (req, res, next) => {
  res.set('Cache-Control', 'no-store, no-cache, must-revalidate, max-age=0');
  next();
});

3. The shocked Brady photo flickered on first scroll.

The 3.2 MB image only started downloading the moment it became visible — which happened to be the same moment we needed to fade it in. <link rel="preload"> moves the fetch to page load so it's already in cache when the scroll happens. 

index.html — <head><!-- Preload hero impact assets so the first-scroll transition is smooth.
     Without this, the browser only fetches the image when the impact
     fires, producing a visible stutter on the first play. -->
<link rel="preload" as="image" href="Assets/tom-brady-shocked.png">

06 How it was built

Three months of evenings and weekends. The code — every line of the HTML, every line of server.js, every code comment on this page — was written in collaboration with Claude:

  • Claude Code in the terminal for the actual file edits, debugging, and deploys.
  • Claude on the web for planning, design briefs, and copy.
  • Claude in Chrome for live audits on the deployed site.

The art — every candidate's portrait, the crown, the goat, the shocked Brady, the twelve-part puppet rig — was hand-illustrated by a human designer in Adobe Illustrator and rigged in Rive. Tech makes things move. Art is what makes them worth moving.

The honest split: AI did the engineering scaffolding (debugging mobile scroll bugs, wiring the database, writing this page). Humans did the taste calls — what the page should feel like, when to cut, when to push harder, the fact that Brady should look shocked and not just sad.

07 For you

If you're a developer — clone this repo, strip out the Brady-specific copy, and you have a working scroll-animation template in one HTML file. The hard problems (mobile viewport, preload order, CDN caching, scrub-timeline pre-warming) are solved and commented in the source.

If you're not a developer — this page is the tour I wish someone had given me when I was first looking at sites like this and wondering how. There's no secret. It's a scrub timeline, four moments, hand-drawn art, and a small database. You can do this.

The animation libraries linked above all have free tiers and excellent docs. Start with GSAP's ScrollTrigger page and Rive's getting-started guide. Read three pages of each, then come back here and View Source.
